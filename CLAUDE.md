# CLAUDE.md — how this project is developed

ARGO's role-based plugin suite for REDCap operations. Users are clinical researchers, mostly
non-technical, reached **Cowork-first** (claude.ai desktop with a connected folder); Claude Code
is the development environment. Four roles organize everything: project manager, QA specialist,
database manager, data analyst.

**Read before working:** `PLAN.md` (the current campaign — governs what to do next) and
`plugins/argo-core/skills/redcap-api/references/access-tiers.md` (the decision record: key
policy, environment facts, settled forks). Decisions recorded there were made deliberately —
don't relitigate them silently; revise them explicitly, with the reason, dated.

## Architecture doctrine

- **Single source of truth, always.** Lists, versions, search paths, tracker definitions live in
  exactly one place. Where duplication is unavoidable (vendored scripts), it is *mechanized*:
  `release.py` syncs, a test fails on drift. Never hand-maintain two copies of anything.
- **Skills are self-contained.** Every skill carries its own `scripts/` (synced from
  `argo-core/skills/redcap-api/scripts/`). Imports are same-folder. Never reach across plugins;
  never glob plugin roots from a script (guard-tested). Four environment layouts broke
  cross-plugin discovery before this rule; a fifth cannot.
- **Where a script lives says who owns it.** A skill's OWN scripts sit at the skill's root
  (`skills/link-data/diff_payload.py`); the SHARED ones vendored from argo-core sit in that
  skill's `scripts/` — so anything in a `scripts/` folder is a synced copy, never edited there.
- **argo-core is plumbing.** Its capabilities surface *through* role skills. Only `start-here`
  (the door) competes for user triggers.
- **Roles route, tasks shape.** The door asks who you are (once — `ARGO_ROLES=` in the settings
  file); skills behind each door are shaped around that role's tasks, not the API surface.

## User-facing doctrine

- **Plain language, no exceptions.** Every error message and instruction must work for someone
  who has never opened a terminal. "Access key," not "API token," with one-line explanations.
- **Ask first, explain on demand.** One confirming line, then one question. Never a menu of two
  ways to do the same thing — pick the right one and say what you did.
- **Keys never transit the chat** — not typed, not in widgets. Files only; verify after.
- **Token-optional forever:** no skill may hard-require a key; every workflow has a
  files-from-the-website path.
- **Never invent data semantics.** Blanks stay blank; unknowns become [TODO]; data-dictionary
  decisions get surfaced to the user one at a time.

## Release discipline

- `python3 release.py --bump patch|minor|major` is the **only** release path. It sets all
  versions in lockstep, stamps `TOOLKIT_VERSION` (printed at runtime by --ensure/--check),
  syncs every vendored copy, and **refuses to complete if the test suite fails**.
- Sessions snapshot plugins at conversation start; org marketplace refresh is manual. Assume
  every live session is stale until its own output proves its version.
- Prefer batched releases over inline fixes. During a declared freeze: log nits (don't fix),
  one batch per day maximum.

## Testing

- `python3 tests/run_all.py` — must pass; needs no network, tokens, or patient data.
- Business logic gets known-input/known-output tests (the worst shipped bug produced no crash —
  only wrong Excel files). Doc/code agreement gets guard tests that read the code's constants.
- Fixtures are **synthetic only** (`testing/fixtures/`), generated by seeded committed
  generators with a MANIFEST.json of exact engineered counts. Never commit patient data, real
  tokens, or real exports. The Cowork test loop (`testing/cowork/round.py`) checks
  agent-behavior/UI on top — it is the second tier, not the only tier.

## Process rules (each one paid for)

- No pipelines around exit-critical commands — `| tail` eats exit codes; check `$?` explicitly.
- Block-editing files: verify anchor **order** before slicing (an empty slice "succeeds");
  grep the file on disk afterwards. `py_compile` cannot detect a deleted function.
- After layered edits to any SKILL.md, read it **whole** — the worst doc bugs were
  contradictions between individually-correct edits.
- Failed Cowork round → mine the transcript (`~/Library/Application Support/Claude/
  local-agent-mode-sessions/*/…/audit.jsonl`) before writing any fix. Check the version stamp
  first; don't debug behavior that a stale org refresh explains.
- Claims about environments get verified empirically, never assumed — every "obviously it works
  like X" about Cowork has been wrong at least once.

## Secrets and safety

- Local credentials: `~/.argo/.env` (0600). Test baseline with real keys lives **outside** the
  connected workspace (`~/Desktop/ARGO-cowork-rounds/baseline/`) — a connected folder is
  readable in full by every session.
- Writes to REDCap: project confirmation before every write (client does it), diff-shown,
  receipt-gated for patient data (`push_updates.py`). Read the Tier table before adding any
  write path.
- This repo is **public**. Nothing with staff contact details, tokens, or patient data —
  official Word templates are *fetched* from the File Repository, never committed.
