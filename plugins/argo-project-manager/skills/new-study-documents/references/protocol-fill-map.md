# Filling the ARGO Protocol Template

**The template is the authority, and it explains itself.** `ARGO Protocol Template/ARGO Protocol
Template.docx` in the File Repository carries an italicised instruction under almost every
heading, saying what that section must contain. **Read those instructions and follow them.** Do
not paraphrase them here, do not replace them with your own idea of what a protocol section
should say, and never draft a section you have not read the instruction for.

This file exists for the one thing the template cannot tell you: **where each answer comes from**
— which sections a study proposal already answers, which only a person can answer, and which have
a standing ARGO answer you can propose. That is the difference between a protocol drafted in one
sitting and a protocol that comes back with forty `[TODO]`s in it.

**The template's own standing rules, which govern everything below:**

- Every `[bracketed placeholder]` is either replaced or answered **"Not applicable"**. A protocol
  silent on a question reads as an oversight — the template says so itself.
- Every italicised instruction, and the version line on the cover sheet, is **deleted before
  submission**.
- Sections marked *(remove if not applicable)* may be deleted in full. **Nothing else may be.**
- **Do not renumber** until the whole document is drafted.

## Where each section's content comes from

`Proposal` = mine it from the study proposal or concept note. `PI` = ask; only a person knows.
`Biostat` = the named biostatistician, who the template requires **before the protocol is
circulated for review**. `ARGO` = there is a standing programme answer — propose it, PI confirms
(see the next section). `Other doc` = it comes from, or must agree with, another ARGO document.

## ARGO's standing answers

These are the programme's usual answers to the template's recurring blanks — drawn from ARGO's
own approved protocols and its live REDCap practice. **Propose them; the PI confirms.** They are
defaults, not facts about this study: an unconfirmed one stays a visible `**[TODO: …]**` rather
than becoming an asserted regulatory claim. Institutional details in particular — approval
references, retention periods, backup schedules, who administers the database — change, and a
protocol that asserts one that was never confirmed is worse than one that asks.

| The template asks | ARGO's usual answer |
|---|---|
| Hosting institution (14.2) | Obafemi Awolowo University Teaching Hospitals Complex (OAUTHC) — the OAU REDCap instance |
| Database administrator (14.2) | OAUTHC; study-specific configuration by the ARGO database manager at the PI's request |
| Permission audit cadence (14.2) | At minimum biannually, and at every change of study staff |
| Backup schedule (14.2) | Nightly, by the hosting institution's IT service |
| Who receives exports, how often (14.2) | The study biostatistician, de-identified, at agreed intervals |
| Second participant identifier (14.3) | The hospital number |
| What is scanned into REDCap (14.3) | Signed consent forms and completed questionnaires — **within 24 hours of the consent being signed**, together with the completed eligibility checklist and supporting source documentation |
| PI record audits (14.4) | Biannually |
| Study team meetings (14.4) | Monthly — accrual, data quality queries, deviations, open audit findings |
| Incentives (6.3) | None offered |
| Data and safety monitoring (14.5) | Not required for a minimal-risk observational study — **state the reason, don't just assert it** |
| Authorship (14.7) | ICMJE criteria; every participating site that contributed participants is represented |

The approval body and reference for PHI storage, the retention periods, the room or cabinet where
paper records are held, and the institution's data-protection contact have **no** standing answer.
Ask, or leave the `[TODO]` visible.

## Choosing the consent scenario (7.0)

The template offers four and expects you to **delete the ones that don't apply**. Getting this
wrong is expensive: the scenario has to match the ICF, the HREC application and section 4.1's
consent criterion.

- **7.1 Written informed consent** — the default for a prospective ARGO study.
- **7.2 Documentation waived (verbal)** — minimal risk, and no procedure that would need written
  consent outside research.
- **7.3 Participant signs without a consent discussion** — electronic or read-and-sign.
- **7.4 Consent waived entirely** — the usual choice for a **retrospective** records review where
  participants cannot be traced or have died.

**A study that is both prospective and retrospective keeps two scenarios** and says plainly which
applies to which part. That combination is common in ARGO database studies — check the design in
5.1 before deleting anything.

**A waiver is granted by the committee, never asserted by the protocol.** Write it as applied
for, and say so in the hand-off.

## Cross-document consistency — check these before the draft leaves you

The template demands each of these in its own words. They are the failures that a reviewer
catches and a drafting session does not:

1. **2.0 ↔ 11.0 ↔ 12.3** — every objective has a corresponding analysis, and every analysis
   serves an objective.
2. **8.2 ↔ the questionnaire ↔ the REDCap data dictionary** — the same items in all three.
3. **9.0 ↔ the ICF's study calendar ↔ the questionnaire's structure.**
4. **7.x ↔ the ICF ↔ the HREC application** — the same consent scenario in all three.
5. **10.0 ↔ the ICF** — what happens to data on withdrawal must match *exactly*.
6. **5.2 ↔ Appendix I ↔ 6.1's accrual table ↔ the questionnaire's site field** — one list of
   sites, four places. A real ARGO final listed six sites in the protocol while the questionnaire
   offered a single checkbox reading OAUTHC.
7. **14.4 ↔ the study QA plan** — the protocol states the cadence, the QA plan operationalises it.
8. **5.5 / 12.6 ↔ 13.1 ↔ 14.1 / 14.2 / 14.6 ↔ the ICF** — if software or AI is used anywhere, it
   has to be described consistently everywhere, including in what the participant consents to.

## What blocks a protocol going out

Say these plainly in the hand-off rather than filling them with something plausible:

- **No named biostatistician.** The template requires one on the cover sheet before the protocol
  is circulated for review, and 12.1–12.4 cannot be written without one.
- **No sample size, or no basis for it** — a power calculation, a precision target, or a census
  with the expected number and where that expectation comes from.
- **No ethics committee(s) of record.**
- **No consent scenario chosen.**
