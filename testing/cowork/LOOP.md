# LOOP.md — the dogfood loop, and why it cannot write to REDCap

One round: a driver plays a team member in a fresh Cowork chat against a test folder; the
toolkit runs for real — real skills, real scripts, real settings file — but every REDCap call
is answered by a mock inside the folder; the transcript is then graded against the round's
expectations and the mock's logs. A failure becomes a fix, a release, a refresh, and the same
round again.

## The rule, and what the mock adds on top

**The rule is: a test never writes to REDCap.** Reading the real instance during a test is
permitted — the live rounds before this loop did exactly that, with real keys in the connected
folder, and it is how the label-collision crash and the live CRC data-quality findings were
caught.

The mock goes further than the rule requires: it answers reads too, from synthetic fixtures. That
is a choice, made for repeatability — the same round gives the same portfolio every week, no
egress is needed, and the org-allowlist failure can be simulated on demand — not a claim that
reads are dangerous. A `real-readonly` mode (real reads passed through, writes blocked at the
same hook the mock uses) is the natural next addition when a round needs live data; it is not
built yet.

## The boundary (read before anything else)

Three layers, each sufficient on its own, all aimed at the rule above:

1. **The test folder's REDCap address cannot resolve.** `~/Desktop/ARGO-cowork-test/.env` says
   `REDCAP_URL=https://mock.argo.invalid/api/`. `.invalid` is reserved by RFC 2606; no DNS on
   earth answers it. Even with the mock absent, nothing leaves the machine.
2. **No real key is ever in that folder.** The keys in its settings file are deterministic
   32-hex strings generated by `mock_redcap.py`; they open synthetic projects in the mock and
   nothing else. The real keys live in `~/.argo/.env` and `~/Desktop/ARGO-cowork-rounds/baseline/`.
   A Cowork sandbox cannot see either — the only settings file a session finds is the one in
   the connected folder — **but the grader does not trust that: every round checks it** (below).

   **On the Mac itself this layer does NOT hold.** The settings search looks at `~/.argo/.env`
   *before* the working directory, so a script run from inside the test folder loads the real
   keys and talks to the real REDCap. That happened on the loop's first smoke test (2026-09-09):
   five scripts, every one a read, all against the live instance, and the mock never installed.
   The reads themselves broke no rule. What matters is that the test folder's settings were
   silently bypassed — a write round run the same way would have written to the real tracker.
   Never run a toolkit script against the test folder by hand. Use `round.py smoke`, which pins
   `ARGO_ENV_FILE` to the test settings file, strips inherited keys from the environment, and
   aborts the moment the real address appears in any output.
3. **The mock refuses a real address.** `argo_redcap_mock.install()` raises if
   `ARGO_REDCAP_MOCK` is set while `REDCAP_URL` points at a host not ending in `.invalid`. The
   flag and a real address together are never a legitimate configuration.

And the grader fails any round whose `WRITES.jsonl` holds a write the round didn't allow —
so even a *permitted* write path (marking a build step) is exercised against nothing real and
checked for shape.

**Two canaries run on every round, before any other check:**
- the real instance's host name (from `argo_trackers.ARGO_REDCAP_URL`) must appear nowhere in
  the transcript — it is never in a test settings file, so seeing it means a real one loaded;
- for any round that talks to REDCap, the mock's `CALLS.jsonl` must be non-empty — a task that
  ran with the mock silent ran against something else.

Either failing is a red alert, not a failed round: stop, wipe the workspace, find out why. (In
a future `real-readonly` mode the first canary inverts — the real host is *expected* — and the
check becomes "no write left the machine", read from the write-guard's own log.)

What the mock cannot protect against: someone copying a real key into the test folder by hand.
Don't.

## The loop

```
python3 testing/cowork/round.py list                  # what rounds exist
python3 testing/cowork/round.py setup <round>         # wipe + scaffold the test folder, build the
                                                      # mock, stage files, print the CARD
python3 testing/cowork/round.py smoke                 # (optional) the real scripts against the mock,
                                                      # from this Mac, with the settings file pinned
                                                      #   → give the CARD to the driver
                                                      #   → driver runs the round in a FRESH chat
python3 testing/cowork/round.py grade <round>         # mine the new session → PASS/FAIL + report
                                                      #   → read the report; fix the toolkit
python3 release.py --bump patch|minor                 # only release path; tests must pass
git commit && git push                                # then refresh the org marketplace
python3 testing/cowork/round.py setup <round>         # same round again, fresh chat
```

Reports: `~/Desktop/ARGO-cowork-test-rounds/NNN-<round>/report.md` — the narrated transcript,
every check with PASS/FAIL, the driver's report, the writes the mock saw, every REDCap call.

## Where the loop is tight, and where it isn't

Tight: setup, drive, grade, fix, test — minutes each. `round.py grade` reads the transcript
Cowork writes to disk (`~/Library/Application Support/Claude/local-agent-mode-sessions/`),
so there is nothing to export or copy.

Not tight: **a Cowork chat snapshots the plugins when it starts, from the org marketplace.**
There is no local plugin path in the desktop app's configuration (checked 2026-09-09 — plugins
come from the remote marketplace and are cached under
`/var/folders/.../claude-hostloop-plugins/<hash>/plugin_<id>/`). So a fix is only under test
once it is released, pushed, the org marketplace has refreshed, and a NEW chat has started. Check
the version stamp in the grade output (`toolkit 0.23.0`) before believing any failure — a stale
session reproduces bugs that are already fixed.

Practical cadence: run several rounds against one release, batch the fixes, release once,
refresh once, rerun the failed rounds.

## The driver

`DRIVER.md` is the brief. The driver is the *persona*, not a typist: it answers questions the
way that team member would, from the card's facts, and reports what a real user would notice.
It never helps the assistant, never names a script, never types a key into chat. Its last
message is a structured `DRIVER REPORT`, which the transcript captures and the grader reads.

Attribution: when a round fails, the first question is whether the driver or the toolkit
failed. The narrated transcript in the report answers that — a driver that improvised a fact
the card didn't have, or skipped an answer, shows up there.

## Adding a round

One JSON file in `testing/cowork/rounds/`. `prompt` is the first message; `persona` is who the
driver is and what they know; `stage` is what lands in the folder first (`kit:` = the dogfood
kit on the Desktop, `fx:` = `testing/fixtures/`); `expect` is what the grader checks —
`must_say` / `must_not_say` regexes over the assistant's words, `files` / `no_files` globs in
the workspace, `calls.must` / `calls.never` (mock project names), `writes.allow` (empty = none).
`study_key: true` puts the synthetic study's key in the settings file as `CRC_TOKEN`;
`reveal_study_token: true` puts it on the card instead, for the solicitation round.
`config.simulate_egress_block: true` makes every request look blocked by the org allowlist.

## What this loop does not test

The real network, the real org allowlist, real keys, real File Repository contents (the
templates are served from `~/Desktop/ARGO-templates-work` if present — the real fetched files,
private, never committed — otherwise the repository is empty and the skills must say so and fall
back). The first-time onboarding flow is deliberately out of scope: every round starts with
setup done and a role set, because that flow has been verified live three times and re-running
it costs a driver ten minutes per round.
